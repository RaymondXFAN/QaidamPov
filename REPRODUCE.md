## 2. Reproduction Targets

The paper reports **9 experimental results** across 4 tables. Each can be reproduced by a single command.

### 2.1 Table 3 — Static Classification (Multi-Model)

| Row | What | Command |
|-----|------|---------|
| Random Forest | Static classification on flattened features | Re-run `02_train_dual.py --mode rf` (not implemented in public release; see paper footnote) |
| XGBoost | Static classification on flattened features | Re-run `02_train_dual.py --mode xgb` (not implemented in public release) |
| Vanilla CNN (single-task) | Single-task baseline | Run `python 02_train_baseline.py --mode single` (separate script) |
| Prithvi+LoRA (n=3) | Foundation model fine-tuning | `python 03_train_prithvi.py` |
| **Dual-task CNN (n=6)** | **Proposed method** | `python 02_train_dual.py --mode both` |

### 2.2 Table 4 — Change Detection Per-Class

Produces the per-class precision/recall/F1 breakdown. Automatically generated by `04_eval_all.py`.

### 2.3 Table 5 — λ-Ablation

| Configuration | Command |
|---------------|---------|
| λ = 0.3 | `python 02_train_dual.py --mode single --lambda-change 0.3 --seed 42` |
| λ = 0.5 | `python 02_train_dual.py --mode single --lambda-change 0.5 --seed 42` |
| λ = 0.7 | `python 02_train_dual.py --mode single --lambda-change 0.7 --seed 42` |
| λ = 1.0 | `python 02_train_dual.py --mode single --lambda-change 1.0 --seed 42` |

All four runs share seed=42 and base architecture, varying only λ.

### 2.4 Table 6 — Seed Sensitivity

For the paired comparison (3 seeds at λ=1.0):

```bash
python 02_train_dual.py --mode single --lambda-change 1.0 --seed 42
python 02_train_dual.py --mode single --lambda-change 1.0 --seed 123
python 02_train_dual.py --mode single --lambda-change 1.0 --seed 2024
```

The `--mode both` flag runs all of the above plus the λ-ablation in one go.

## 4. Comparison with Paper Results

The expected outputs should match the paper within ±0.02 (the noise floor from cuDNN non-determinism in some operations).

### 4.1 Allowable Variance

| Metric | Paper | Expected Range |
|--------|-------|---------------|
| Accuracy | 0.824 | 0.804 – 0.844 |
| IoU | 0.803 | 0.783 – 0.823 |
| F1-macro (change) | 0.360 | 0.335 – 0.385 |

### 4.2 Common Causes of Variance

1. **Different cuDNN version**: Set `torch.backends.cudnn.deterministic = True` (already done in our scripts)
2. **Different PyTorch version**: 2.0.0 vs 2.1.0 may give slightly different conv results
3. **Different NumPy version**: Random number generator behavior changes
4. **Different hardware**: GPU architecture affects some ops (FP16 paths)

### 4.3 If Results Differ Significantly

1. Run `python -c "import torch; print(torch.__version__); print(torch.cuda.is_available())"` — verify versions
2. Re-run with explicit seed setting
3. Compare your `results/eval_all_results.json` to the paper's expected values
4. If still problematic, open a GitHub issue with the error log

## 5. Custom Experiments

### 5.1 Try a Different Model Backbone

Edit `code/02_train_dual.py` and replace `DualTaskModel` with your own architecture. The training loop is model-agnostic.

### 5.2 Try a Different Change Class Definition

Edit `code/02_train_dual.py` to change the 4-class definition:

```python
# Original: 0=stable non-saline, 1=stable saline, 2=expansion, 3=shrinkage
# Alternative: 0=stable, 1=change (binary)
```

### 5.3 Try a Different Dataset

The data pipeline expects 6-band Sentinel-2 patches. To adapt to a different region:

1. Replace `data/processed_dual/` with your own patches
2. Ensure the same shape: `(N, 6, 128, 128)` for X, `(N, 128, 128)` for Y
3. Re-run from Step 2
